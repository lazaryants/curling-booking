# Curling Booking

Веб-система бронирования кёрлинговых дорожек с личным кабинетом пользователя и административной панелью.

Проект предназначен для самостоятельного бронирования временных слотов на кёрлинговых дорожках, подтверждения заявок администратором и ведения полной истории бронирований без физического удаления данных.

## Возможности

### Для пользователей

- регистрация и авторизация;
- просмотр расписания дорожек;
- дневной и недельный режимы расписания;
- создание бронирований;
- просмотр собственных активных и исторических бронирований;
- отмена бронирования с учётом установленного временного ограничения;
- личный кабинет с историей бронирований.

Публичное расписание показывает занятость слота, но не раскрывает персональные данные владельца чужого бронирования.

### Для администратора

- просмотр всех активных пользователей;
- создание и редактирование пользователей;
- архивирование пользователей с сохранением истории;
- просмотр бронирований пользователей;
- подтверждение новых заявок;
- отклонение заявок;
- отмена подтверждённых бронирований;
- фильтрация бронирований по статусу и дате;
- административное недельное расписание.

При удалении пользователя его запись архивируется, а не удаляется физически. Исходный email освобождается для повторной регистрации, а связанные бронирования сохраняются.

## Статусы бронирования

Система использует следующие статусы:

- `pending` — ожидает подтверждения администратора;
- `confirmed` — подтверждено;
- `cancelled_by_user` — отменено пользователем;
- `cancelled_by_admin` — отменено администратором;
- `rejected_by_admin` — отклонено администратором;
- `completed` — завершено.

Отменённые, отклонённые и завершённые записи сохраняются в базе данных, но больше не блокируют соответствующий временной слот.

## Автоматическое обновление статусов

Отдельная периодическая задача проверяет бронирования каждые 15 минут.

Она:

- переводит `pending` в `rejected_by_admin`, если время начала слота уже наступило;
- переводит `confirmed` в `completed`, когда время окончания бронирования прошло.

Расчёт времени выполняется в часовом поясе `Europe/Moscow`.

## Безопасность и целостность данных

- JWT-аутентификация;
- после архивирования пользователя его существующий JWT больше не даёт доступа;
- публичное расписание не раскрывает данные чужих бронирований;
- серверная валидация email, имени, телефона, пароля и роли;
- атомарное изменение статусов бронирования;
- защита от конфликтующих одновременных операций;
- защита от двойного активного бронирования одного временного слота;
- администратор не может удалить собственную учётную запись или снять с неё роль администратора.

## Интерфейс

Frontend выполнен на Vue 3 и адаптирован для настольных и мобильных экранов.

В интерфейсе реализованы:

- дневное расписание двух дорожек;
- недельное расписание;
- личный кабинет;
- административная панель;
- цветовая индикация статусов;
- собственные модальные окна вместо системных `alert()` и `confirm()`;
- адаптивные карточки пользователей и бронирований;
- стилизованный фон кёрлингового льда;
- собственный SVG-логотип кёрлингового камня и favicon.

## Backend: настройка окружения

Создайте файл:

~~~text
backend/.env
~~~

на основе:

~~~text
backend/.env.example
~~~

Необходимые переменные:

~~~env
DB_HOST=localhost
DB_PORT=3306
DB_NAME=curling_booking
DB_USER=curling_booking
DB_PASSWORD=change_me
SECRET_KEY=change_me
~~~

Настоящий `.env` содержит секретные данные и не должен попадать в Git.

## Установка backend

~~~bash
cd backend
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
~~~

Запуск для разработки:

~~~bash
uvicorn main:app --host 127.0.0.1 --port 8000
~~~

## Установка frontend

~~~bash
cd frontend
npm install
npm run dev
~~~

Production-сборка:

~~~bash
npm run build
~~~

## Проверка подключения к базе данных

В проекте присутствует простой диагностический скрипт:

~~~bash
cd backend
python test_db.py
~~~

Он использует параметры подключения из `backend/.env`.

## Production-развёртывание

Production-развёртывание предполагает:

- backend под управлением systemd;
- nginx как reverse proxy и сервер статического frontend;
- HTTPS;
- MySQL;
- периодический запуск `cleanup_bookings.py` через systemd timer.

Конкретные production-секреты, сертификаты и серверные конфигурации в репозиторий не включаются.
